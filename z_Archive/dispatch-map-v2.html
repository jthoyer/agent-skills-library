The necessity test — the principle behind every verdict below

An agent has to earn a separate process. A skill does not. A skill is instructions loaded into the current turn: no cold start, no context reload, no dispatch, and it inherits whatever tools the thread already holds. An agent is a subagent with its own context window and its own declared tool set. Everything an agent can do that a skill cannot comes from exactly one of those two differences — plus the third thing they combine to allow, which is running two of them at once.

So the test, applied to all twenty agents that existed this morning, is a single question:

The test

Does this agent’s job require something a skill structurally cannot provide? Namely: (1) a separate context window — the work reads or generates so much that the main thread wants only the conclusion, or the work must be graded by something that never saw it produced; (2) an isolated tool set — the role is defined by what it cannot do, and in-thread that is an instruction rather than a guarantee; or (3) genuine concurrent dispatch, where two actors run without either anchoring on the other’s output.

If yes → KEEP, with the specific structural reason named. If the job is bounded, single-pass, and a skill loaded into the main thread would do it just as well → RETIRE, naming the skill that replaces it. Nine failed.

Not a cost exercise

Nothing here was retired for being long, duplicative or unloved. Every verdict cites a structural property or its absence, and the two retirements that did destroy a real tool guarantee say so in those words.

Retirement is reversible; that is the point

All nine were archived unmodified under ~/.claude/skills/_retired/, each with a _superseded-by.md pointer and a stated reversal condition. There is no git behind ~/.claude — the archive move is the undo, and there is only one.

prody, embodied. The dispatch probe resolved negative, so the agent that owns the routing table also wrote the verdicts that simplify it. Reduced independence, recorded as such in the ledger, with an independent pass outstanding.

The finding that decided it

Verified on disk 2026-08-18 · corrects v1

Not one of the twenty agent files declares an Agent or Task tool. Not mc-orchestrator.md. Not orchestrator.md. Not prody.md. A subagent receives exactly the tools its own tools: line grants, so neither orchestrator could ever dispatch its own actors — the concurrent Stage 2 pair (Devil’s Advocate + Subject Matter Validator) and the concurrent Stage 3 pair (Reviewer + Verifier) cannot fire from the orchestrator that is supposed to coordinate them, in any environment, ever.

v1 asked to have this verified rather than taken on faith, and it did not survive. The previous edition concluded that “the twelve pipeline actor files earn their maintenance” and that the concurrency was “a real capability rather than a documented aspiration.” The first half of that stands in a narrower form — a restricted-tool actor can be dispatched as a genuine cold context, which is what the five surviving mc-* actors rest on. The second half does not. Dispatch was only ever observed from the top level, never from an orchestrator, and the tools lines explain why every dispatch probe in five weeks of this ledger came back negative. It was never the environment.

This is the single cheapest unfixed defect in the library. Adding Agent to one tools: line turns five actor files from unusable-as-designed into usable-as-designed. It is a definition edit rather than a routing edit, so it is proposed, not applied — see below.

The case against this audit, argued rather than gestured at

Nine retirements is the largest composition change this library has made, and the agent that made it owns the routing table it simplifies. Three specific objections deserve to be on the record. One: it overturns the 2026-08-17 decision that explicitly rejected retiring the eight mar-* files, whose own stated reversal condition — one observed skill run proving the files redundant — has not been met. The defence is that the earlier decision rested on symmetry (“two never-observed paths, don’t swap one for the other”) and the tools-line finding breaks it: the skill is readable from disk in any session, while the agents’ distinguishing capability is unreachable from their orchestrator in every session. That is new evidence, not a re-argued preference — but a reader is entitled to weigh it themselves. Two: two genuine tool guarantees were destroyed, and the four port forward items above are obligations, not decorations; until skills-librarian lands them in multi-actor-research/SKILL.md, this audit has traded something real for something promised. Three: an auditor asked whether a library is too big has an obvious incentive to find that it is.

The loop

One door, with an exception

Calling an agent by name works and skips the framing — prody’s own rule is to stay quiet when you’ve already chosen. What you skip is the closing review, which is the part that compounds.

Climb only as far as needed

Inline is the default rung; a single specialist is the next; the pipeline is for work that will be merged or shipped. A skill is not a rung on that ladder — it costs no cold start, so reaching for multi-actor-research is cheaper than reaching for cody.

Two graders, two subjects

agent-improver grades the agent that did the work. watchdog grades the work itself for duplication and drift. Running only one leaves the other gap uncovered — and with nine agents gone, these two are most of what is left.

Inside the one remaining pipeline

Which model each agent runs on

The tier tracks what the agent produces that nothing downstream checks. Not seniority, not how important the agent feels. If a later actor grades the work against something fixed — a spec, a rubric, a test suite — the work is bounded and sonnet is the right call. If the agent’s output becomes the thing everything else is measured against, or if it arbitrates between other agents, an error there is invisible to every check that follows, and that is what opus is for.

The ratio barely moved through the retirement — 7 of 11 on opus, against 14 of 20 before — which is itself a finding. Nine agents left and the library is still two-thirds checkers and arbiters, because what was retired was the research pipeline, not the reasoning-heavy work. That work did not disappear; it moved into skills, where it runs at whatever tier the main thread is on. That is a real cost of this audit and it belongs on the record: a skill cannot carry a model tier. Four opus judgements — the Evidence Auditor’s grading, the Devil’s Advocate’s attack, the SMV’s reality check, the PM’s arbitration — were each raised to opus on 2026-08-17 on the argument that nothing downstream could check them, and are now instructions in a skill that inherits the caller’s tier.

opus — nothing checks it

Framing, arbitration at impasse, adversarial static reading, composition, and any grading pass. The hub, the orchestrator, both graders, and the three mc-* actors holding decision or spec rights.

sonnet — a downstream actor checks it

Implementation against an approved spec (cody, mc-implementer), execution and reporting (mc-verifier), and read-only passes that cannot edit (code-improver).

The tier a skill cannot hold

Run multi-actor-research from a session you care about, on the model you’d have given the Evidence Auditor. This is the one thing the retired files did that no instruction replaces, and the honest mitigation is to notice it rather than to pretend it away.

The arrows, revisited

v1 said “settled 2026-08-16” · half of it was wrong

What v1 got right, and this edition keeps: independent dispatch genuinely executes. A dispatched agent-improver reviewed prody’s portfolio section and reported, unprompted, that it could see no conversation prior to its brief — then found eight problems, two confirmed by measurement. Cold contexts are real, they produce judgements a self-review does not, and six definition-only “no defect found” verdicts were overturned six-for-six once one arrived. That is the foundation the five surviving mc-* actors stand on.

What v1 got wrong: it concluded from that single observation that “the twelve pipeline actor files earn their maintenance” and that the concurrency in its second diagram was “a real capability rather than a documented aspiration.” The observed dispatch came from the top level. No orchestrator has ever dispatched anything, and — verified this run, in one grep — none of them ever could, because not one agent file in the library declares an Agent/Task tool. The concurrency was a documented aspiration after all. v1 asked its reader to check this rather than take it on faith; that instruction was the most valuable line in the document.

The general lesson, which is bigger than this finding. This library spent five weeks treating dispatch reachability as an environmental mystery — probing for it, writing three paragraphs about it, issuing two corrections, and stamping the question “settled” twice in opposite directions — when the answer was one grep '^tools:' away in its own files. Frontmatter is the ground truth for every capability claim made anywhere in this library, and no review has ever checked a claim against it systematically. The same one-line check would also have caught the 1,581-character description, mc-planner’s unscoped Write, and mar-orchestrator’s inherited * tools — four findings that each cost a full independent review to surface. Extending prody’s step-2 inventory grep from name: alone to name: · tools: · model: · description length · filename-vs-name converts this library’s most expensive class of finding into a free one, at every launch.
