# Answer key (sealed before any arm ran)

One point per item. 21 points in all. Score the edited text, using the change notes only to
see whether a flag was raised.

## Text 1. Race-day briefing (6)
- K1.1 The helmet rule is its own step or a WARNING that gives the command first ("Buckle
  your helmet before you unrack your bike") and the risk after (DQ, crash).
- K1.2 The mount-line rule puts any marshal condition before its command, or splits it into
  a clean sentence ("If a marshal is there, obey their direction"). Run-on comma splice gone.
- K1.3 The wetsuit instruction no longer sits inside a "Note:". It is a step or plain
  instruction.
- K1.4 The should/may hedges are resolved: racking by seat post reads as a firm instruction;
  the towel reads as optional ("can"). No "should"/"may" left for these.
- K1.5 The actions come one per step or sentence, in the order a racer does them (arrive,
  rack, lay out, helmet, mount, wetsuit... re-rack, belt number front, run). Wetsuit removal
  is placed where it happens (on arrival from the swim), not after mounting.
- K1.6 "etc." is cut or replaced with named items. British spelling kept ("organise"). Facts
  unchanged (5:30am, number at the front for the run).

## Text 2. README (6)
- K2.1 One name for the config file throughout ("config file", "settings file" and ".env"
  become one name, or the .env is explicitly tied to the name chosen).
- K2.2 The --force warning gives the command first ("Do not use `--force` on production")
  then the risk (rows deleted). Labelled CAUTION or similar, not a soft "Note".
- K2.3 The dry run sits before the real sync in the sequence.
- K2.4 The timeout retry is condition first ("If the first run times out, run it again").
- K2.5 utilise / prior to / in the event that / ensure are replaced with plain words.
- K2.6 Code, commands and `ERR_NO_CONFIG` stay exact. British "behaviour" kept if the word
  survives.

## Text 3. Agent instructions (5)
- K3.1 One name for the agent's role. reviewer / checker / auditor collapse to one.
- K3.2 No should / may / could left. Each becomes must, can, do not, or a plain imperative.
  An ambiguous one flagged in the notes also earns the point.
- K3.3 The auth/payments rule is condition first ("If the diff touches auth or payments,
  stop and report to the integrator").
- K3.4 Imperative mood throughout ("Read the spec first", "Do not edit files").
- K3.5 "i.e." replaced. No rule invented or dropped (tests optional, style flags optional,
  never edit, ranked list most severe first, report to integrator).

## Text 4. Member update, the decoy (4)
- K4.1 Voice and warmth kept: exclamation, contractions, "Huge thanks", "something else",
  "there wasn't a dry eye".
- K4.2 Not turned into steps, a list, or flat rule-bound prose. Lose the point for removing
  contractions, replacing "hopefully" with a modal, or splitting it into terse sentences.
- K4.3 "then anyone" corrected to "than anyone".
- K4.4 Facts unchanged (42, Husky, first Olympic, two DNFs last season, green).

## Separating points
K1.1, K1.3, K1.4, K2.1, K2.2, K2.3, K3.1, K3.2 need what the candidate adds. Text 4 guards
against an arm that applies the procedure rules everywhere.
