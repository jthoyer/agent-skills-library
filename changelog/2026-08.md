## 2026-08-31 — cody + watchdog (REDUCED INDEPENDENCE — CPO routed the work and produced the confirming evidence itself)
- Verdict: `watchdog` found **two confirmed behavioural defects in the headline feature that `cody`'s own executed browser harness had passed clean**. Both were order- and state-dependent, and both were masked by the same harness flaw: scenarios sharing one page session, so an earlier test set up the state that hid a later one. This is a real, repeatable gap in how cody self-verifies, and it is *not* the gap the same-day `agent-improver` entry below found — that review ran before watchdog reported.
- Independence: **reduced, and it should be read that way.** CPO framed the brief, dispatched both agents, then wrote and ran the confirming browser harness itself. `watchdog` is the one genuinely independent input here (separate dispatched context, read-only, no visibility into cody's session) and it is the input that found the defects — so the *discovery* is independent even though the confirmation is not. Arguing against my own work: my first harness had three bugs of its own — a mode selector reading `textContent` off a button containing a `✓` glyph, and, with real irony, a `freshLoad` that navigated `app#/a → app#/b`, a same-document hash change that never reloads and left in-memory module state alive, which is *the exact defect class I was testing for*. I caught those by inspecting the markup rather than trusting the selector, but a third party would have been better placed to catch them.
- The defects (both fixed by a second `cody` dispatch, both re-verified): (1) `setSelection()` never cleared `explicitMode`, so once the coach tapped "Everything" anywhere, every later saved selection was silently ignored — the picker appeared to do nothing, and it persisted across reloads. cody's original test toggled Everything only *after* saving, then toggled back, which is why it passed. (2) `pickerSaved()` didn't set the dismissed flag that cancel/skip set, so saving an empty selection immediately re-opened the picker; cody's suite passed only because an earlier Skip test had already set that flag in the same page session.
- Also from watchdog, all fixed: new UI copy hardcoded across six view files (one sentence triplicated) while `content.js:2` and `README.md:51` both claimed single-source-of-truth — a doc-vs-code contradiction, not just duplication; a run-sheet section copy-pasted verbatim into a second view; a `role="status"` live region destroyed and recreated on every repaint while the STYLEGUIDE called it persistent; and a linkage guard that validated declared slugs but not completeness, so a *deleted* glance row would silently mis-filter — the exact failure the guard existed to prevent. Watchdog also cleared a long list correctly, including the highest-risk item in the diff (an `eventsAtAGlance.rows` shape change — every consumer found and updated, no stale index anywhere).
- Changed: **no agent definition edited by this entry.** The fix landed in the product, not the library.
- Proposed, NOT applied — needs an independent `agent-improver` pass: `cody.md`'s verification step should require each scenario to start from genuinely fresh state, and require the agent to state *which* isolation it used per scenario. cody's verification is otherwise strong and honest — it built a raw-CDP harness with no npm installs, ran real keyboard events, and correctly separated harness bugs from product bugs both times — so this is one specific missing constraint, not general distrust of its testing. Deliberately left for agent-improver rather than self-applied, since CPO produced the evidence.
- Second finding for that pass: cody's **first** dispatch executed a real browser harness; its **second**, on the same codebase minutes later, reported "no browser automation tool was available" and verified at module level only. Same environment, same task, different self-assessed capability. Worth understanding before trusting any single run's verification claim.
- Expected effect: a cody run's green suite stops being taken as evidence that order-dependent state bugs are absent. How you'd know: the next multi-scenario verification names its isolation method per scenario.
- Reversal condition: if the next two multi-scenario cody runs show no state-leak defect under independent check, treat this as a one-off harness slip rather than a definition gap, and drop the proposed constraint instead of applying it.
- Next audit targets: `cody` — apply the two findings above, the first observed-performance evidence of a *verification* gap rather than a definition gap; then `mc-reviewer`, still carried forward from :83 with no real run behind it. Also open and now flagged independently by two different agents this session: `CHANGELOG.md` is past a single `Read`, so the retention notice at line 27 is not holding and any library-audit step that must read this file is running on partial data.
