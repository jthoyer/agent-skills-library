Where COS sits

COS is a personal Chief of Staff, not a member of the library CPO governs. It holds no portfolio authority here — it doesn't add, retire, or merge agents, and it doesn't enter CPO's dispatch line in the diagram below. It routes into this library, and into skills outside it, from its own table:

  • Everything consequential COS produces is staged at ~/.claude/COS/staging/ for approval — never sent, published, or executed directly.
  • Before a decision of consequence, COS names a mentor from the Mentors & Board Members database in Notion and states their idea in one line. Decisions that changed an actual action are logged to a Notion decision-log database, mirrored locally at ~/.claude/COS/decision-log.md so the count can't go silently stale.
  • COS never orchestrates a build itself — that's still mc-orchestrator, reached the same way CPO reaches it.
  • A domain mandate at ~/.claude/COS/mandate.md, versioned and reviewed monthly, defines what COS is even trying to optimise for. Nothing in that definition is hard-coded into cos.md itself.

Inline self-review

Two agents check their own output against a different party — a skill, never themselves — before returning it, rather than waiting for CPO's closing review after the fact:

AgentRoutes toCloses
codycode-review skillThe gap left by a standalone dispatch having no downstream check, unlike mc-implementer
mc-plannerred-team skillThe one spec error nothing else in the pipeline catches
  • Both route to a skill, not an agent — holds the library's own rule that no actor grades its own work, and needs no new Agent tool grant.
  • Doesn't replace CPO's closing review: this checks the immediate output; watchdog and agent-improver check different things, on a longer cycle.
  • Scoped to these two only — most other agents are either already checked inside their own pipeline, or are themselves the checking mechanism.

How the library got here

v4 dropped the narrative of prior versions in favor of an appendix. v5 kept that shape and added two entries at the end for what changed since. v6 does the same, plus a correction to something v5 got wrong. The decisions behind the current 12-agent shape, kept for reference:

  • The library started at 20 agents. A necessity test was applied to each: does the job require a separate context window, an isolated tool set, or genuine concurrent dispatch — something a skill loaded into the current turn structurally cannot provide? If not, the agent was retired in favor of a skill.
  • 9 agents failed the test and were retired: 10x → first-principles skill; mar-orchestrator, mar-researcher, mar-evidence-auditor, mar-devils-advocate, mar-subject-matter-validator, mar-synthesiser, mar-project-manager → multi-actor-research skill; mar-communicator → scr-pyramid-communicator skill.
  • All nine were archived unmodified at ~/.claude/skills/_retired/<name>/, each with a pointer to its replacement and a stated reversal condition. There is no git behind ~/.claude; the archive move is the undo.
  • The finding that drove the audit: none of the 20 original agent files declared an Agent/Task tool, so no orchestrator could ever dispatch its own actors — concurrency that looked designed-in was never actually reachable.
  • That gap was closed for the two agents where it mattered: Agent was added to mc-orchestrator.md's and prody.md's tools: lists, so both can now genuinely delegate rather than only embody, when a session's dispatch tool is itself reachable.
  • Inline self-review was added to two agents (cody, mc-planner) — scoped down from an initial broader proposal after a wider authorized-execution dispatch was blocked by the auto-mode classifier. Each routes to a skill, never itself.
  • Two tool-guarantee losses were accepted as real, not argued away: mar-subject-matter-validator had no search tool at all, forcing it to speak only from knowledge or admit it couldn't; mar-evidence-auditor had no WebSearch. Both constraints now live only as instructions inside the skill that replaced them.
  • Open follow-up, tracked in the Notion backlog, not here: porting four things the retired research agents held — register persistence, the SMV's "where your knowledge runs out" section, the PM's escalation checklist, the Researcher's coverage note — into multi-actor-research/SKILL.md.
  • New in v5 — the hub's dispatch name changed from prody to CPO, at direct user instruction, no further rationale given. Only the frontmatter name: field moved; the file stays prody.md, matching this library's own convention that filename and dispatch address may diverge (the retired mar-orchestrator lived in orchestrator.md). Cross-references in cody.md and agent-improver.md were updated in the same pass, along with the one inbound dependency outside this library — prompt-refiner's Phase 4 execution step. v1 through v4 are left saying "prody" throughout, as point-in-time snapshots of the library when each was written.
  • New in v5 — a routing boundary and a verification pattern, added the same day as the rename. mc-planner and built-in Plan had overlapped on the same trigger ("design an approach before code exists") since the library's founding; the boundary is now persistence — Plan when nothing downstream reads the answer, mc-planner when a spec must be consumed by mc-implementer/mc-reviewer/mc-verifier. Separately, agent-improver and watchdog gained instructions to verify one specific claim directly — a targeted Grep/Glob/Read, the same check an Explore dispatch would do — rather than trust a work sample's own narration, scoped down after adding them an Agent tool was blocked by the auto-mode classifier.
  • Correction, v6 — the CPO rename was more complete than v5 recorded. The bullet immediately above claims the file "stays prody.md." That was wrong: confirmed 2026-08-18, while building COS, that the file is CPO.md — it was renamed along with the frontmatter name: field, not just the dispatch name. Left the v5 bullet unedited above, per this doc's own stated policy of preserving prior entries as point-in-time snapshots rather than rewriting them; this note is the fix going forward.
  • New in v6 — COS, a personal Chief of Staff, added 2026-08-18. COS sits above this library rather than inside it: no portfolio authority over what agents exist (that stays CPO's, unchanged), but it routes into the library — for builds, code, product decisions, pressure-testing — from its own table (see "Where COS sits"). It brings three mechanisms this library didn't have before: a mandate read fresh each session from ~/.claude/COS/mandate.md rather than hard-coded into the agent, so domain definitions can be revised monthly without touching agent logic; a headline number — decisions made with a framework behind them — logged to a Notion database and mirrored locally so the count can never silently go stale; and a staging discipline at ~/.claude/COS/staging/ so nothing consequential leaves without approval. A PostToolUse hook (cos-audit.py) logs every Write/Edit it makes to ~/.claude/COS/audit/log.jsonl, and fails silently on any error rather than ever blocking a tool call. Verified end to end the same day: /brief produced the full six-part format against live Notion data, including a real, un-softened finding (ten job leads stalled since 2026-08-06).
